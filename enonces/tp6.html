Partie A — Comprendre & exploiter

A.1 — Le point d'entrée

Le back-office importe des réglages au format YAML (POST /admin/import-settings). L'appli utilise js-yaml 3.13.1 avec load(), qui accepte le type !!js/function : il construit une vraie fonction JavaScript à partir du YAML.

A.2 — RCE via !!js/function

Construire la fonction ne suffit pas : il faut qu'elle soit appelée. On piège la clé toString, appelée dès que l'objet est concaténé à une chaîne (ce que fait le code en journalisant les réglages). Dans une fonction créée ainsi, require n'existe pas directement : on passe par process.mainModule.require.

POST /admin/import-settings   (champ yaml)

"toString": !<tag:yaml.org,2002:js/function> "function(){process.mainModule.require('child_process').execSync('id > /tmp/yaml_pwn.txt')}"
RCE complète via un simple champ YAML. Aucun scanner dynamique ne la trouve sans connaître le type maison !!js/function.
Question 1. Preuve d'exécution. Pourquoi faut-il passer par toString et process.mainModule.require ?

Partie B — Détecter & corriger en CI/CD

B.1 — Le piège de version (à retenir absolument)

En js-yaml v3, load() est dangereux et il fallait penser à safeLoad(). En v4 (2021), ils ont inversé : safeLoad a été supprimé et load() est sûr par défaut (les types !!js/function ne sont plus dans le schéma par défaut). Un dev qui suit un vieux tuto ou reste en v3 se fait avoir ; un autre migre v3→v4 et son safeLoad casse.

B.2 — Détection

Conséquence : cette faille se détecte surtout par SCA (version de la dépendance), pas par un motif de code — car le même load() est dangereux en v3 et sûr en v4. Ajoutez .github/workflows/06-sast-yaml.yml : le job sca-yaml échoue si js-yaml < 4 ; le job semgrep-yaml signale l'API v3 obsolète (safeLoad).

B.3 — Corriger

npm install js-yaml@^4.1.0      # (déjà dans le package.json fourni)

Remplacez src/routes/admin.js par la version fournie : yaml.load() sur js-yaml v4, sûr par défaut. Les types !!js/function sont refusés.

B.4 — Vérifier

npm test    # tests/yaml.test.js

Le payload !!js/function est inerte, un YAML légitime fonctionne, la gate SCA passe (js-yaml ≥ 4).
