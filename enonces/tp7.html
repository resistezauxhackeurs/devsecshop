Partie A — Comprendre & exploiter

A.1 — Le sink

L'export catalogue construit une commande shell à partir du champ format que vous contrôlez :

execSync('echo "Export au format ' + format + '"')

En injectant des métacaractères shell, on exécute des commandes arbitraires :

POST /admin/export
format = csv"; id > /tmp/cmdi_pwn.txt; echo "
RCE directe. Le DAST peut parfois la détecter en aveugle (fuzzing de métacaractères), mais le SAST la voit clairement dans le code : donnée utilisateur → commande shell.
Question 1. Preuve d'exécution. Quels métacaractères shell permettent d'enchaîner des commandes ?
Correction 1

Preuve d'exécution

Avec format = csv"; id > /tmp/cmdi_pwn.txt; echo ", le fichier /tmp/cmdi_pwn.txt contient la sortie de id : la commande injectée s'est exécutée. La valeur ferme le guillemet du echo, puis ; enchaîne notre propre commande, et le echo " final rééquilibre les guillemets pour que la ligne reste valide.

Métacaractères d'enchaînement

  • ; : séquence (exécute les commandes l'une après l'autre, sans condition) ;
  • && / || : enchaînement conditionnel (si succès / si échec) ;
  • | : pipe (la sortie de l'une devient l'entrée de l'autre) ;
  • $(...) et les backticks `...` : substitution de commande.

B.1 — CodeQL : l'analyse de flux

Ajoutez .github/workflows/07-sast-codeql.yml. CodeQL suit le flux de données (data flow) : il relie la source (l'entrée HTTP) au sink (execSync) et confirme le chemin d'attaque, avec moins de faux positifs qu'un simple motif. La règle Semgrep fournie fait le repérage rapide par motif.

B.2 — Corriger

Remplacez src/routes/admin.js par la version fournie. Le fix supprime totalement le shell :

  • Liste blanche de formats (csv / json) : toute autre valeur est rejetée (400).
  • Le CSV/JSON est généré en JavaScript, sans child_process.
Règle générale : préférer ne pas lancer de shell. Si un binaire externe est indispensable, utiliser execFile/spawn avec un tableau d'arguments (jamais de chaîne concaténée passée à un shell).
💡 Théorie & méthode

La bonne défense n'est pas « échapper le shell » mais ne pas lancer de shell du tout. Ici l'export CSV/JSON se fait très bien en JavaScript pur, sans child_process. Quand une commande externe est vraiment indispensable, on utilise execFile/spawn avec un tableau d'arguments (jamais une chaîne concaténée passée à un shell) et on valide l'entrée par liste blanche.

Fonction / outil à utiliser : liste blanche de formats (csv/json) + génération du fichier en JS ; à défaut execFile(cmd, [args]) sans shell.

Voir la correction (code)
// ❌ AVANT — entrée utilisateur concaténée dans une commande shell
const { execSync } = require('child_process');
const out = execSync('echo "Export au format ' + format + '" ');

// ✅ APRÈS — liste blanche + génération en JS, aucun shell
const format = String(req.body.format || 'csv').toLowerCase();
if (format !== 'csv' && format !== 'json') {
  return res.status(400).send('Format non supporté (csv ou json).');
}
const products = db.prepare('SELECT id, name, price_cents, stock FROM products ORDER BY id').all();
if (format === 'json') {
  return res.type('application/json').send(JSON.stringify(products, null, 2));
}
const esc = (v) => '"' + String(v).replace(/"/g, '""') + '"';
const header = 'id,name,price_cents,stock';
const rows = products.map((p) => [p.id, esc(p.name), p.price_cents, p.stock].join(','));
res.type('text/csv').send([header, ...rows].join('\n'));
