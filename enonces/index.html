DevSecShop - Page TP

Récupère le lab, lance-le en Docker, et pour chaque TP : exploite la faille, corrige-la, reteste.

Lab volontairement vulnérable. À lancer en local uniquement, jamais exposé sur Internet.

1. Récupérer le dépôt

Remplace l'URL par celle du dépôt GitHub qui t'a été communiqué.

git clone https://github.com/resistezauxhackeurs/devsecshop.git
cd app_devsecshop

Prérequis : Docker Desktop (ou Docker Engine + Compose v2) et git. Rien d'autre à installer : Node tourne dans le conteneur.

2. Lancer l'application

docker compose up --build -d     # app -> http://localhost:3000
docker compose logs -f app       # logs
docker compose down              # arret

Comptes de démo : admin, alice (mot de passe password), bob.

3. Lancer les tests (dans Docker)

Le npm test direct suppose Node 20 en local ; dans ce lab on passe par Docker :

# Linux / macOS / Git Bash
./scripts/test.sh
# Windows
scripts\test.bat

4. Récupérer le correctif de référence

Essaie d'abord de corriger toi-même. Pour comparer ou débloquer, chaque TP a une branche solution cumulative :

git fetch origin
git diff main origin/solution/tp3    # comparer ta correction au corrige du TP3
git checkout solution/tp3            # ou basculer sur l'etat corrige
git checkout main                    # revenir a l'etat vulnerable

5. Les TP

TP 0 · intro

Comment une appli se fait compromettre

Intro45 minAppli PHP séparée · port 8080

Avant de défendre, voir une compromission complète de bout en bout : d'un champ de login jusqu'à l'exécution de commandes sur le serveur.

  • SQLi : admin'-- - (entrer sans mot de passe)
  • Récupérer les identifiants admin
  • Upload d'un webshell (Content-Type falsifié)
  • RCE : uploads/shell.php?cmd=id
💡 Astuce. Fais l'upload sous Kali/WSL/Linux (-F "image=@shell.php;type=image/png") ou via Burp : le curl de Windows a un bug sur l'envoi de fichier.
✅ Résultat attendu. uploads/shell.php?cmd=id renvoie uid=33(www-data) : tu exécutes des commandes sur le serveur = compromission totale.
🚀 Lancer ce lab (séparé, à la racine du dépôt). 
cd intro
docker compose -f docker-compose.local.yml up -d --build   # -> http://localhost:8080

TP 5 / 8

Désérialisation non fiable (RCE)

Niveau 21 hSAST + SCA (invisible au DAST)

Un cookie de préférences désérialisé avec node-serialize exécute du code.

  • Cookie prefs (base64)
  • RCE via _$$ND_FUNC$$_
💡 Astuce. La charge est une IIFE : {"x":"_$$ND_FUNC$$_function(){require('child_process').execSync('…')}()"} encodée en base64 dans le cookie prefs.
✅ Résultat attendu. Après passage au JSON pur : aucun code exécuté à la lecture des prefs, Semgrep au vert.
🔧 Corrige la vuln puis reteste.

git diff main origin/solution/tp5

TP 6 / 8

Désérialisation YAML (js-yaml)

Niveau 21 hSCA (version) + SAST (API)

L'import de réglages YAML avec js-yaml v3 exécute !!js/function.

  • Import de réglages YAML
  • RCE via !!js/function
💡 Astuce. require n'existe pas dans le scope de la fonction : passe par process.mainModule.require('child_process'). Le vrai correctif = js-yaml v4.
✅ Résultat attendu. Après migration v4 : aucune exécution ; le job SCA exige js-yaml >= 4 ; Semgrep flague la version 3.x dans package.json.
🔧 Corrige la vuln puis reteste.

Logique métier, ReDoS & capstone

Niveau 3 · Capstone1 h 45Gate CI + sécurité conteneur

Ce qu'aucun scanner ne trouve seul : IDOR, mass assignment, quantité négative, ReDoS. Puis verrouiller la pipeline.

  • IDOR sur /account/orders/:id
  • Mass assignment : is_admin=1
  • Quantité négative (total < 0)
  • ReDoS sur le code promo
💡 Astuce. ReDoS : un coupon "A"×40 + "!" fige l'event loop. Mass assignment : ajoute is_admin=1 au POST de profil.
✅ Résultat attendu. Après fix : 404 sur l'IDOR, is_admin non forçable, total ≥ 0, checkout rapide, et la gate CI bloque si une faille réapparaît.
🔧 Corrige la vuln puis reteste.
